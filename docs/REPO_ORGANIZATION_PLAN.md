## 🧹 2. Audit Rules (What to Archive/Private)

Perform a manual audit of all your existing repositories:
- **Make Private / Delete:**
  - Old school assignments.
  - Abandoned tutorials or "hello world" projects.
  - Projects with messy code or no README.
- **Archive (Read-Only):**
  - Completed projects that you no longer maintain but are proud of (e.g., old QA frameworks you built).
- **Keep Public & Active:**
  - Tools that people can actually use.
  - Packages or libraries you maintain.
  - Your main products (like TabComet).

## 🏷️ 3. Naming & Tagging Conventions

- **Repository Names:** Use lowercase, hyphen-separated names (e.g., `tab-comet`, `ai-summarizer`).
- **Descriptions:** Every repo must have a 1-2 sentence description. Do not leave it blank.
- **Topics (Tags):** Add at least 4-5 topics to every public repo to improve GitHub SEO discoverability.
- **Website Link:** Always link to the Chrome Web Store URL, documentation site, or a live demo in the repository's "About" section.

## 🖼️ 4. Social Preview Images

Every public repository should have a custom social preview image (Open Graph image).
- **Dimensions:** 1280 × 640 pixels
- **Design:** Use the same dark mode background as your profile banner. Place the product logo in the center and the product name/tagline below it.
- **Why:** When your repo is shared on Twitter, LinkedIn, or Slack, it will look like a premium software product, not just a code dump.
